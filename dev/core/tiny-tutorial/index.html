Tutorial: Find a Leak on Tiny

New

This tutorial runs a whole ALVIE experiment on Tiny, the reference platform of ALVIE/Core. Tiny is a small processor written in OCaml, so learning a model takes a fraction of a second, and you need no simulator and no Sancus checkout. It has two planted timing leaks: one that any attacker sees, and one that only an attacker with interrupts sees. The steps are those of an experiment on Sancus (see Getting Started), and How ALVIE Works explains the ideas behind them.

You need the OCaml build of ALVIE (dune build in alvie/code, for example in the Docker image), or nothing at all: the tutorial Tiny of ALVIE in your browser runs these steps in your browser, with the same commands. mCRL2 is needed only to check formulas. Run every command from alvie/code.

1. The platform

Section titled “1. The platform”

Tiny runs the attacker’s code or the code of one enclave. The attacker arms a timer with timer n and calls the enclave with call. Each instruction of the enclave takes one or two cycles, and the timer counts them. When the timer expires during an instruction, the instruction completes and then the interrupt is handled: the attacker sees the interrupt and its latency, the cycles the instruction still ran after the timer expired. The attacker’s ISR runs, and reti resumes the enclave. When the enclave returns (ret), the attacker sees how many cycles it ran since it was called or last resumed.

The enclave’s instructions:

InstructionCycles
nop, mov r, v, ret1
bz r (branch on zero)2 if r is 0, 1 otherwise
pad r (pads a branch on zero)1 if r is 0, 2 otherwise

The plugin files are in plugins/tiny/, and the backend is lib/core/tiny/tiny.ml.

5. Compare them

Section titled “5. Compare them”

alvie tiny compare looks for runs that the attacker tells apart: the same attacker inputs, the same enclave code up to the secret, and different outputs.

The exit status is 4 when there are witnesses, so scripts can test it. Render the witness graph with Graphviz (dot -Tsvg /tmp/tiny/time-witnesses.dot -o witnesses.svg) and read it as Reading and Checking a Witness explains: one witness is the run without a timer, where the enclave returns after Exit(time = 4) for secret 0 and Exit(time = 3) for secret 1.

6. Is the leak caused by interrupts?

Section titled “6. Is the leak caused by interrupts?”

Learn the same spec on the variant no-interrupts, whose timer never expires, and give it to compare as the baseline: witnesses that the baseline has too do not count.

Every witness is already there without interrupts: the leak of bz is the time the enclave takes, which any attacker sees.

7. A leak that only interrupts reveal

Section titled “7. A leak that only interrupts reveal”

plugins/tiny/fixtures/leak-interrupt.spec pads the branch:

bz r0; pad r0 takes three cycles whatever the secret, so without interrupts nothing leaks. Learn the four models and compare, first the baseline on its own, then with interrupts against it:

The witnesses arm the timer with timer 2 or timer 3. With timer 2, the timer expires in the first cycle of bz for secret 0, a latency of 1, and at the end of bz for secret 1, a latency of 0: the interrupt tells the secret, as the attack of Nemesis does on Sancus.
